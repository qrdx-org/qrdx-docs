The node's REST API is on the same host as JSON-RPC (testnet: `https://test.qrdx.org`). Responses are `{"ok": true, "result": …}` or `{"ok": false, "error": "…"}`; the operations endpoints answer plain text or JSON. Parameters are query parameters on `GET` and a JSON body on `POST`; `?` marks optional ones.

<Callout type="warn" title="Rate limits">Public nodes limit requests per IP and endpoint. `get_blocks` is also cost-limited: each call costs `offset / 100 + limit / 50` against a budget of 1,000 per IP per hour, so deep or wide block ranges are expensive. Prefer the [transaction index](/docs/build/transaction-history) and [streams](/docs/build/streams).</Callout>

## Chain

| Endpoint | Params | |
| --- | --- | --- |
| `GET /get_status` | — | Height, last block hash and node id. Not cost-limited. |
| `GET /get_block` | `block`, `full_transactions?` | One block by height or hash. |
| `GET /get_blocks` | `offset?`, `limit?` | Blocks from `offset`, ascending. Cost-limited per IP (see below). |
| `GET /get_transaction` | `tx_hash` | A transaction by hash. |
| `GET /get_address_info` | `address`, `transactions_count_limit?`, `page?`, `show_pending?` | Balance and recent transactions of an address (either form). |
| `GET /get_validators` | `status?` | Return the PoS validator set from the validators table. |
| `GET /get_attestations` | `slot?`, `epoch?`, `validator_address?`, `block_hash?`, `limit?`, `offset?` | Get attestations by slot, epoch, validator, or block |
| `GET /get_pending_transactions` | — | The mempool. |
| `GET /get_unified_state_root` | — | Return the unified block state root (Whitepaper §3.6): a BLAKE3-512 commitment over all state domains — UTXO set, account/EVM state, exchange state, and the QRC-20 token ledger. |
| `GET /get_randao_mix` | — | The accumulated RANDAO mix (observe-first) — a deterministic fold of every canonical block's proposer reveal (see qrdx.validator.randao). All honest nodes on the same chain MUST report an identical mix; this endpoint is how that cross-node convergence is confi |

## Transaction index

| Endpoint | Params | |
| --- | --- | --- |
| `GET /get_address_history` | `address`, `limit?`, `cursor?`, `kinds?` | Everything an address did or received — legacy transfers, exchange operations (token moves, swaps, orders and the fills of its resting orders, pools, perps, staking), EVM transactions and the token transfers they emitted — newest first, with each transaction's |
| `GET /get_latest_transactions` | `limit?`, `cursor?`, `kinds?` | The chain's latest transactions of every kind, newest first (paged like `/get_address_history`). |
| `GET /get_indexed_transaction` | `tx_hash` | One indexed transaction of any kind — its block, status, fee, summary and every account it touched with their roles. |

## Exchange transactions

| Endpoint | Params | |
| --- | --- | --- |
| `POST /exchange_signing_payload` | JSON body | The exact bytes an exchange transaction's sender signs, for these fields (`op_type` as a number or name, `sender`, `nonce`, `params`, optional `gas_limit` / `gas_price`), and the hash the transaction will have. Sign `signing_bytes` with the sende |
| `POST /submit_exchange_tx` | JSON body | Submit a signed exchange transaction (spot, perps, staking, oracle votes — every exchange op). |
| `GET /get_exchange_receipt` | `tx_hash` | The executed result of an exchange transaction — success or failure, its error, and the operation's data (an order's id and fills, a deposit's collateral, …). `null` while it is pending (or after it ages out of this node's journal). |

| `GET /get_exchange_state_root` | — | Return this node's current exchange state root (Whitepaper §3.6 BLAKE3-512). |

| `GET /get_nfts` | `owner`, `collection?`, `limit?` | An owner's NFTs (its 0x or 0xPQ address), every collection or one. |

## Market data

| Endpoint | Params | |
| --- | --- | --- |
| `GET /get_markets` | `kind?` | Every market's ticker — spot pairs (order book and/or AMM pools) and perps markets: top of book, last price, 24h open/high/low/change/volume. `kind` = spot \| perp. |
| `GET /get_ticker` | `market` | One market's ticker. `market` is a spot pair `base:quote` (addresses, unique symbols or QRDX, either order) or a perps market id. |
| `GET /get_orderbook` | `market`, `depth?`, `level?` | A market's order book: level 2 = price levels with running base/quote totals, level 3 = every resting order per level in time priority; plus best bid/ask, spread (and in bps), mid, last price, the block height it reflects and, for a spot pair, its AMM pools. |
| `GET /get_trades` | `market`, `limit?`, `since?` | A market's recent trades, oldest first — order-book fills, AMM swaps, perps fills — with the taker's side and the transaction. `since` (a trade `seq`) returns only newer ones. |
| `GET /get_candles` | `market`, `interval?`, `limit?`, `end?` | OHLCV candles by block time (1m 5m 15m 1h 4h 1d). |

## Operations

| Endpoint | Params | |
| --- | --- | --- |
| `GET /healthz` | — | Liveness probe — the process is up and serving. Always 200. |
| `GET /readyz` | — | Readiness probe — the node can serve chain data (DB reachable, a tip exists). 503 if not, so a load balancer / orchestrator drains this node until it is caught up. |
| `GET /metrics` | — | Prometheus text exposition — chain height, finality, peers, stream subscribers, etc. |
